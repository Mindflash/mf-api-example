Use this endpoint to add users to the Trakstar Learn system. The user information supplied must contain the basic information, but can optionally include group information and course/series enrollment information.
Note: Between 1 and 200 users may be submitted per API call. 

{
  "users": [
    {
      "firstName": "",
      "lastName": "",
      "email": "",
      "username": "",
      "permissions": 169000100
    }
  ],
  "requiredCourseIds": [],
  "courseIds": [],
  "seriesIds": [],
  "groupIds": [],
  "clientDatestamp": "",
  "batchId" : 1
}
Note When posting json data in the body of the request, the Content-Type must be set to application/json.
Field Optional Notes
users NO A list of all users information to be added to the Trakstar Learn system.
Field Optional Max Length Notes
firstName NO 35 Users first name.
lastName NO 35 Users last name.
email YES* 254 Users email address.
username YES* 254 Unique username for user.
permissions YES N/A One of:
169000100 — Trainee (Default)
169000200 — Manager
169000300 — Trainer
169000400 — Administrator
169000500 — Reporter
169000600 — Team Lead
yammerId YES N/A Yammer ID of user.
password YES 35 A login password, 8 to 35 characters, containing an uppercase letter, lowercase letter, number, and symbol. A supplied password is subject to the account's password-expiry policy: it expires once the account's password lifetime elapses, and the user is then prompted to set a new password at their next login.
* Note: At least one of email or username must be supplied. Both may be supplied. When permissions explicitly specifies Trainee (169000100), supplying username requires password. When permissions explicitly specifies another documented role, supplying both username and password also requires email.
requiredCourseIds YES A list of Trakstar Learn course IDs to enroll the users in. All users will be enrolled in these courses with the required option enabled.
courseIds YES A list of Trakstar Learn course IDs to enroll the users in. All users will be enrolled in these courses with the required option disabled.
seriesIds YES A list of Trakstar Learn series IDs to enroll the users in. All users will be enrolled in these series.
groupIds YES A list of Trakstar Learn group IDs to place the users in. All users will be placed into these groups.
clientDatestamp YES Defaults to the current date if omitted. All dates must be in the format YYYY-MM-DD.
batchId YES An identifier for this specific API call. If omitted, a default value is used. Upon success, the value is returned in the response.
mode YES Defaults to import, which updates existing users matched by email or username. With any other truthy value, the request fails if a submitted user matches an existing user by email or username.

The Trainee default applies only to new users. When updating an existing user matched by email or username, omitting permissions preserves the user's existing role. Updating a matched archived user reactivates the user and consumes a seat, so the request can fail with HTTP 400 and code max_users_reached if the account has insufficient capacity.

Response

A successful response includes batchId, an added list of new users and an updated list of existing users that were updated. Each entry contains the user's id and available email and username. A missing email or username may be null or omitted. Either list is empty when no users were added or updated, respectively.

Examples

Example: Add 2 trainees and enroll in 3 courses, 1 which is required. 
POST https://api.mindflash.com/api/v2/user

{
  "users": [
    {
      "firstName": "Tom",
      "lastName": "Jones",
      "email": "tjones@yourorg.com"
    },
    {
      "firstName": "Rumple",
      "lastName": "Stilskin",
      "email": "rumple@yourorg.com"
    }
  ],
  "requiredCourseIds": [ 1234 ],
  "courseIds": [ 6789, 6543 ],
  "seriesIds": [],
  "groupIds": [],
  "clientDatestamp": "2013-07-17",
  "batchId" : 122
}
					
Response: 200
{
  "batchId": 122,
  "added": [
    { "id": 12345, "email": "tjones@yourorg.com", "username": null },
    { "id": 12346, "email": "rumple@yourorg.com", "username": null }
  ],
  "updated": []
}
Updating an existing user

With the default import mode, when an existing user is matched by email or username, the response lists that user under updated instead:

POST https://api.mindflash.com/api/v2/user

{
  "users": [
    {
      "firstName": "Thomas",
      "lastName": "Jones",
      "email": "tjones@yourorg.com"
    }
  ],
  "batchId": 123
}
					
Response: 200
{
  "batchId": 123,
  "added": [],
  "updated": [
    { "id": 12345, "email": "tjones@yourorg.com" }
  ]
}
